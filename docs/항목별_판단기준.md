# 항목별 판단 기준 (2026 KISA 가이드)

> Unix 서버 > 1. 계정 관리 / 2. 파일 및 디렉토리 관리

## U-01 root 계정 원격 접속 제한 (상)
- 점검 내용: 원격터미널 접속 차단 설정 적용 여부
- 양호: 원격터미널 미사용, 또는 사용 시 root 직접 접속 차단
- 점검(SSH): /etc/ssh/sshd_config 의 PermitRootLogin 값이 no
- 조치: PermitRootLogin No 설정 후 sshd 재시작
- 참고: CentOS 8·Ubuntu 20.04+는 Telnet 기본 비활성, /etc/securetty 없음

## U-02 비밀번호 관리정책 설정 (상)
- 양호: 비밀번호 관리 정책이 설정된 경우
- 점검(RHEL): /etc/security/pwquality.conf (minlen=8, dcredit/ucredit/lcredit/ocredit=-1)
  또는 /etc/pam.d/system-auth 중 하나라도 설정되어 있으면 양호
- 만료: /etc/login.defs PASS_MAX_DAYS 90, PASS_MIN_DAYS 1
- 참고: 복잡성 최소 요구 값은 반드시 -1로 설정해야 적용됨

## U-03 계정 잠금 임계값 설정 (상)
- 양호: 계정 잠금 임계값이 10회 이하
- 점검(RHEL): /etc/pam.d/system-auth, /etc/pam.d/password-auth 의
  pam_faillock(또는 pam_tally2) deny=10 unlock_time=120
- 참고: RHEL 8+는 authselect 사용 권장, 모듈 경로 틀리면 로그인 불가 주의

## U-04 비밀번호 파일 보호 (상)
- 양호: 쉐도우 비밀번호 사용 또는 비밀번호 암호화 저장
- 점검: /etc/passwd 2번째 필드가 모두 x (root:x:0:0:...), /etc/shadow 존재
- 조치: pwconv 명령으로 쉐도우 적용

## U-05 root 이외의 UID '0' 금지 (상)
- 양호: root와 동일한 UID(0)를 갖는 계정이 없음
- 점검: /etc/passwd 3번째 필드(UID)가 0인 계정이 root뿐
- 조치: usermod -u <새 UID> 로 변경 또는 불필요 계정 제거

## U-14 root 홈·패스 디렉터리 권한 및 패스 설정 (상)
- 양호: PATH 환경변수에 "."이 맨 앞/중간에 없음
- 점검: echo $PATH
- 조치: 환경설정 파일(/etc/profile, ~/.profile, ~/.bashrc)의 PATH에서 "." 제거 또는 맨 뒤로

## U-15 파일 및 디렉토리 소유자 설정 (상)
- 양호: 소유자/그룹이 없는 파일·디렉터리가 없음
- 점검: find / \( -nouser -o -nogroup \) -xdev -ls 2>/dev/null
- 조치: 해당 파일 제거 또는 chown/chgrp로 소유자 변경

## U-16 /etc/passwd 파일 소유자 및 권한 (상)
- 양호: 소유자 root, 권한 644 이하
- 점검: ls -l /etc/passwd  (또는 stat -c '%U %a' /etc/passwd)
- 조치: chown root /etc/passwd; chmod 644 /etc/passwd

## U-17 시스템 시작 스크립트 권한 설정 (상)
- 양호: 시작 스크립트 소유자 root, 일반 사용자 쓰기 권한 제거
- 점검(systemd): ls -al `readlink -f /etc/systemd/system/*`
- 조치: chown root <파일>; chmod o-w <파일>

## U-18 /etc/shadow 파일 소유자 및 권한 (상)
- 양호: 소유자 root, 권한 400 이하
- 점검: ls -l /etc/shadow  (또는 stat -c '%U %a' /etc/shadow)
- 조치: chown root /etc/shadow; chmod 400 /etc/shadow

## U-19 불필요한 서비스 비활성화 (finger·telnet·tftp·talk) (상)
- 점검 내용: 사용하지 않는 서비스가 활성화되어 있는지 여부
- 양호: finger, telnet, tftp, talk 서비스가 비활성화(미설치 포함)
- 점검: /etc/xinetd.d/{finger,telnet,tftp,talk}의 disable 값, /etc/inetd.conf의 주석 여부
- 조치: xinetd.d 설정에서 disable = yes로 변경, 또는 해당 패키지 제거

## U-20 r 계열 서비스 비활성화 (rsh/rlogin/rexec) (상)
- 점검 내용: 평문 인증 기반 r 계열 원격 서비스 및 신뢰 호스트 설정 여부
- 양호: shell/login/exec 서비스 비활성화, hosts.equiv·.rhosts 미사용(또는 내용 없음)
- 점검: /etc/xinetd.d/{shell,login,exec}의 disable 값, /etc/hosts.equiv, ~/.rhosts 존재 여부
- 조치: xinetd.d 설정에서 disable = yes로 변경, hosts.equiv·.rhosts 파일 삭제

## U-21 Anonymous FTP 비활성화 (상)
- 점검 내용: FTP 서버의 익명 접속 허용 여부
- 양호: anonymous_enable이 NO(또는 미설정), 혹은 FTP 서버 미설치(N/A)
- 점검: vsftpd.conf(또는 proftpd.conf)의 anonymous_enable 값
- 조치: anonymous_enable=NO로 설정 후 서비스 재시작

## U-22 SNMP 서비스 및 community string 점검 (상)
- 점검 내용: SNMP community string이 public/private 등 기본값을 사용하는지 여부
- 양호: community string이 기본값이 아니거나 SNMP 미설치(N/A)
- 점검: /etc/snmp/snmpd.conf의 rocommunity/rwcommunity/com2sec 값
- 조치: community 문자열을 추측 불가능한 값으로 변경, 불필요 시 SNMP 서비스 비활성화

## U-23 NFS/NIS 서비스 비활성화 및 접근 통제 (상)
- 점검 내용: NFS 공유 설정의 접근 범위 제한 여부
- 양호: /etc/exports 미사용, 또는 공유 대상 IP가 제한되고 no_root_squash 미사용
- 점검: /etc/exports 내 '*(' 와일드카드 공유 또는 no_root_squash 옵션 존재 여부
- 조치: 불필요한 NFS 공유 제거, 접근 허용 IP를 명시하고 no_root_squash 제거

## U-24 OS 배포판 EOL(지원종료) 여부 점검 (상)
- 점검 내용: 실행 중인 OS 배포판이 벤더의 표준 지원 종료일(EOL)을 지났는지 여부
- 양호: 오늘 날짜가 해당 배포판 버전의 EOL 이전, 또는 EOL 데이터 미보유 시 '수동'
- 점검: /etc/os-release의 ID·VERSION_ID를 스크립트에 내장된 주요 배포판(Ubuntu/Debian/CentOS/RHEL) EOL 표와 대조
- 한계: EOL 표는 점검 시점 기준 벤더 공식 발표일을 하드코딩한 값이라 주기적 갱신이 필요하며, 표에 없는 배포판·버전은 '수동'으로 처리
- 조치: EOL된 배포판은 최신 LTS/안정 버전으로 업그레이드

## U-25 커널 패치 적용 여부(재부팅 대기) 점검 (상)
- 점검 내용: 커널·라이브러리 보안 패치가 설치되었지만 재부팅하지 않아 아직 구버전 커널로 동작 중인지 여부
- 양호: 재부팅 대기 표시가 없음(Debian/Ubuntu는 /var/run/reboot-required 부재, RHEL 계열은 needs-restarting -r 통과)
- 점검: /var/run/reboot-required 존재 여부 → 없으면 Debian 계열은 양호 확정, 그 외 배포판은 needs-restarting(yum-utils) 결과로 판단, 둘 다 불가하면 '수동'
- 조치: 최신 커널 패키지 설치 후 재부팅하여 패치된 커널 적용

## U-26 패키지 매니저 기준 미적용 보안 업데이트 개수 점검 (상)
- 점검 내용: 패키지 매니저 기준으로 설치되지 않은 업데이트(패키지 수)가 있는지 여부
- 양호: 미적용 업데이트 0건
- 점검: apt list --upgradable(헤더 제외 건수) 또는 dnf/yum check-update 결과 건수
- 한계: apt 계열은 로컬 패키지 인덱스가 최신으로 갱신(apt update)되어 있어야 정확한 결과가 나옴
- 조치: apt upgrade 또는 yum/dnf update로 대기 중인 패키지 업데이트 적용

## U-27 마지막 패치 적용 일자(최근성) 점검 (중)
- 점검 내용: 마지막으로 패치(업그레이드)가 적용된 날짜로부터 경과한 일수
- 양호: 마지막 패치 적용일로부터 90일(분기) 이내
- 점검: /var/log/apt/history.log의 마지막 Start-Date(Debian/Ubuntu), 로그가 없으면 '수동'
- 한계: 로그 로테이션으로 과거 기록이 삭제된 경우 실제보다 오래된 것으로 오판될 수 있음(보수적으로 '취약' 방향 오차)
- 조치: 분기 1회 이상 정기 패치 적용 주기를 수립하고 준수

## U-28 핵심 서비스(OpenSSH·OpenSSL) 버전 및 EOL 점검 (상)
- 점검 내용: OpenSSH·OpenSSL이 EOL 되었거나 알려진 취약 버전 대역을 사용하는지 여부
- 양호: OpenSSH 8.0 이상이고 OpenSSL이 1.0.x/1.1.0/1.1.1(2023-09 EOL) 대역이 아님(3.0 이상), 또는 둘 다 미설치
- 점검: ssh -V, openssl version 결과를 버전 기준값과 대조
- 한계: OpenSSH 8.0, OpenSSL 1.1.1 기준은 2026-10 시점 공식 EOL 공고를 반영한 보수적 컷오프이며 신규 CVE 발표 시 갱신 필요
- 조치: 배포판 패키지 매니저로 OpenSSH·OpenSSL을 최신 버전으로 업데이트

## U-29 로그 기록(Syslog) 설정 여부 점검 (상)
- 점검 내용: 시스템 로그가 실제로 기록·보존되고 있는지(syslog 데몬 또는 journald 영구 저장) 여부
- 양호: rsyslog/syslog-ng 설정이 존재(내용 있음), 또는 systemd-journald가 Storage=persistent 이거나 Storage=auto이면서 /var/log/journal 디렉터리가 존재
- 점검: /etc/rsyslog.conf, /etc/syslog-ng/syslog-ng.conf, /etc/systemd/journald.conf의 Storage 값
- 조치: rsyslog/syslog-ng 설치·설정 또는 journald Storage=persistent로 변경하여 로그를 영구 기록

## U-30 주요 로그 파일 소유자 및 권한 점검 (상)
- 점검 내용: syslog/auth 계열 로그 파일의 소유자·권한이 과도하게 개방되어 있는지 여부
- 양호: /var/log/syslog, /var/log/auth.log(또는 messages, secure) 중 존재하는 파일이 모두 소유자 root, 권한 640 이하
- 점검: stat -c '%U %a' 대상 로그 파일
- 수동: 대상 로그 파일을 하나도 찾지 못한 경우(배포판에 따라 파일명이 다를 수 있음)
- 조치: chown root <파일>; chmod 640 <파일>

## U-31 로그 보존 기간(로테이션) 설정 점검 (중)
- 점검 내용: logrotate 전역 보존 주기(rotate)가 침해 추적에 충분한지 여부
- 양호: /etc/logrotate.conf의 전역 rotate 값이 4 이상(예시 기준 — 조직 로그 보관 정책에 맞게 조정 가능)
- 점검: /etc/logrotate.conf의 rotate 값(conf_val로 마지막 매칭 값 사용)
- 한계: logrotate.conf 내 특정 로그별 override 블록이 전역값 뒤에 있으면 그 값이 우선 반영되어 오판될 수 있음(마지막 매칭 기준)
- 수동: logrotate 미설치 또는 설정 파일 없음
- 조치: rotate 값을 조직 정책(예: 4회=약 1개월 이상)에 맞게 상향

## U-32 원격 로그 서버 전송 설정 점검 (중)
- 점검 내용: 로그를 원격 로그 서버로 전송(중앙화)하고 있는지 여부
- 양호: /etc/rsyslog.conf 또는 /etc/rsyslog.d/*.conf 중 하나라도 '@' 또는 '@@'로 시작하는 원격 전송 규칙을 포함
- 점검: rsyslog(.d) 설정 내 '@' 포함 라인(주석 제외)
- 조치: 원격 로그 서버 전송 규칙(예: *.* @@loghost:514) 추가 — 로컬 전용이면 침해 시 로그 조작·삭제 위험

## U-33 감사 로그(auditd) 설치 및 규칙 설정 여부 점검 (상)
- 점검 내용: 계정 변경·권한 상승 등 민감 이벤트를 감사(auditd)로 추적하고 있는지 여부
- 양호: auditctl 명령 또는 /etc/audit/auditd.conf가 존재하고, /etc/audit/audit.rules 또는 /etc/audit/rules.d/*.rules에 주석·공백 제외 1줄 이상의 규칙이 설정됨
- 점검: command -v auditctl, /etc/audit/{audit.rules,rules.d/*.rules} 내용 줄 수
- 조치: auditd 설치 후 주요 이벤트(계정 변경, 권한 상승, 중요 파일 접근 등)에 대한 규칙을 /etc/audit/rules.d/에 등록
